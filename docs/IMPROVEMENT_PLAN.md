### A. 账号生命周期（当前最大缺口）

| # | 缺口 | 现状 | 方案 | 优先级 |
|---|---|---|---|---|
| 1 | **忘记密码 / 找回** | 无任何找回通道，密码丢失 = 账号永久丢失 | 绑定邮箱（注册/登录后可设）→ 找回时签发一次性重置令牌（HMAC+过期时间），邮件或页面链接重置 | **P0** |
| 2 | **修改密码** | 无 | 账号设置页：验证旧密码 → 设新密码（复用现有 PBKDF2 派生链路） | **P0** |
| 3 | **账号注销** | 无（只有退出登录） | 「注销账号」二次确认 → 删除 users 记录 + 该账号所有 readings；wishes 可选匿名化或删除（符合《个保法》删除权） | **P0** |
| 4 | **个人数据导出** | 无 | 账号设置页一键导出本人命运簿 JSON（《个保法》可携带权） | P1 |
| 5 | **匿名 → 账号升级** | 匿名占卜数据只在本设备；注册后不会并入新账号 | 注册/登录成功时，把本机匿名 readings（按旧 device）合并进账号（`owner` 从 device 改写为 uid） | P1 |
| 6 | 多端会话管理 | 无 | 服务端会话表支持「查看登录设备 / 踢出其他设备」（依赖安全改造 #3） | P2 |
| 7 | 个人资料 | 仅用户名 | 昵称、头像（可选）、保研状态标签（可选，用于画像文案） | P2 |

## 三、个人信息安全审视

### 现状亮点（保持）

- 全链路 HTTPS；明文密码不出浏览器（PBKDF2 15 万次派生），服务端只存 `sha256(派生值+随机盐)`
- 会话 = HMAC-SHA256 签名令牌；管理员角色在签名令牌内；普通用户访问 `/api/admin/*` 被拒（已实测）
- `users` 表不暴露给客户端；用户输入一律 `textContent` / `esc()` 渲染
- 零第三方依赖（无供应链风险）；密钥（SESSION_SECRET / API Token）均未进仓库；Cloudflare Token 为最小权限

### 风险与方案（按严重度）

| # | 风险 | 现状 | 方案 | 优先级 |
|---|---|---|---|---|
| 1 | **CORS 全开** | Worker 返回 `Access-Control-Allow-Origin: *` → **任何网站**的脚本都能匿名调我们的接口（刷心事、注册、读全站内容） | 收紧为本站域名白名单（`yalaibao.top` / workers.dev 域名 + 本地调试源）；非白名单 Origin 直接拒绝；同时校验请求 Origin 头 | **P0** |
| 2 | **无速率限制** | 注册/登录无次数限制 → 可暴力破解口令、批量注册、刷屏 | 服务端限流：注册/登录按「IP + 用户名」计数（失败 5 次锁 15 分钟）；发帖/点亮按设备与 IP 限频；可用 D1 计数表或 Cloudflare 免费速率规则 | **P0** |
| 3 | **会话不可撤销** | 登录令牌 30 天、HMAC 无状态 → 令牌泄露后无法主动失效；退出登录仅清本地 | 增加会话表（D1：session_id/user/创建时间/最后活跃），登录签发时登记、退出/踢出即删除；支持「退出所有设备」 | **P0** |
| 4 | **合规文件缺失** | 无隐私政策/用户协议/注销途径（同功能 #3/#16） | 补齐三件套 + 注册时勾选同意 | **P0** |
| 5 | **安全响应头缺失** | 无 CSP / X-Content-Type-Options / X-Frame-Options / Referrer-Policy / HSTS | Worker 统一注入响应头；HSTS 等可在 Cloudflare 面板开启 | P1 |
| 6 | 管理员防护单薄 | 管理员 = 单一因素（Yaya 密码），无审计 | 管理员登录成功/删帖等关键操作写审计日志表；管理台展示最近操作；提示使用强密码 | P1 |
| 7 | 内容安全 | 无举报/过滤（同功能 #8） | 同上 | P1 |
| 8 | 密钥轮换意识 | API Token 曾出现在聊天记录中 | 建议在 Cloudflare 轮换 Token；SESSION_SECRET 提供轮换脚本（轮换会踢掉全部会话，配合 #3 会话表更平滑） | P1 |
| 9 | 数据备份 | 依赖 Cloudflare 托管备份 | `cf_db.mjs` 增加 `dump`（全量导出 JSON/CSV）与 `restore`，定期备份 | P1 |
| 10 | 双因素认证 | 管理员无 2FA | 依赖平台能力，可后置；短期用「强密码 + 限流 + 审计」组合 | P2 |
| 11 | 监控告警 | 无自动告警 | Cloudflare Analytics + Worker 错误日志阈值告警（免费额度内可用）；异常注册量突增提醒 | P2 |

## 五、建议实施路线（三个迭代）

### 迭代一：安全与合规加固（约 1 周，最高优先）

1. CORS 收紧为白名单 + Origin 校验
2. 服务端速率限制（注册/登录/发帖/点亮）
3. 会话表 + 撤销 / 退出所有设备
4. 修改密码 + 账号注销 + 数据导出
5. 隐私政策 / 用户协议 / 免责声明页面 + 注册勾选
6. OG 分享标签（顺手做，影响传播）
7. 安全头注入（CSP 等）

### 迭代二：账号生命周期与内容治理（1–2 周）

1. 忘记密码（邮箱绑定 + 一次性重置令牌）
2. 匿名 → 账号升级（本机记录并入账号）
3. 心事墙举报 + 管理台举报队列 + 基础敏感词过滤
4. 管理员增强：封禁用户、操作日志、置顶
5. 分享落地页（`?s=seed` 链接 + 二维码）
6. 安全测试用例进 CI

### 迭代三：体验与运营（持续）

PWA、首次引导、设置中心、每日一签/好友互抽、运营看板、深/浅主题、品牌字体、骨架屏与空状态、系统分享、监控告警。

## 六、一句话结论

**核心玩法与云端架构已经达到可上线水准；现阶段最该补的不是新功能，而是「账号生命周期」（找回/改密/注销）、「平台安全基线」（CORS 白名单、限流、合规文件）与「传播基建」（OG 标签、分享落地页）——这三块补齐后，产品即从「能玩的游戏」升级为「可信赖的服务」。**
