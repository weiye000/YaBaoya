## 一、整体架构（原理）

### 1. 三层结构

```
┌─────────────────────────────────────────────────────────┐
│ 前端（静态网页）                                          │
│ index.html + src/ + assets/                              │
│ 部署在 CloudBase「静态网站托管」上（一个域名一个环境）        │
│ 玩家打开网址 → 浏览器运行游戏                              │
└───────────────┬─────────────────────────────────────────┘
                │ 通过 CloudBase JS SDK 直连（HTTPS）
┌───────────────▼─────────────────────────────────────────┐
│ 云端（微信云开发环境 cloud1-d9gqiv9hvb5ead833）           │
│  · 文档型数据库：wishes / lights / readings 集合          │
│  · 身份认证：匿名登录（设备级隐形身份）                     │
│  · 静态托管：*.tcloudbaseapp.com（环境自带测试域名）       │
└─────────────────────────────────────────────────────────┘
```

**核心思想**：浏览器**不直接**拿数据库密钥连云端（那样不安全），而是靠两个闸门：

| 闸门 | 作用 | 本项目状态 |
|---|---|---|
| **WEB 安全域名** | 只有被列入白名单的网站才能用 SDK 连这个环境 | 用环境自带托管域名，天然在白名单内 ✅ |
| **集合安全规则** | 每个集合允许谁读、谁写 | 需设为 `{"read":true,"write":true}`（待办） |

### 2. 为什么要「静态托管 + 自带域名」这条路

- 「个人版」套餐**禁止添加自定义 WEB 安全域名**（报错：`当前套餐无法执行此操作`）——所以不能把游戏放 GitHub Pages 再连云端；
- 环境**自带**的托管域名 `cloud1-xxx.tcloudbaseapp.com` 天然在白名单里 → 把前端直接托管在环境上，SDK 访问自动合法；
- 代价：测试域名首次访问会出现官方「风险提醒」页，点「确定访问」即可（浏览器会记住）。**正式运营**需绑定已备案的自定义域名。

### 3. 身份体系（三级）

| 身份 | 原理 | 用途 |
|---|---|---|
| **匿名登录** | 每个设备自动获得一个隐形身份（无需注册） | 让数据库读写有「凭证」，配合公开读写规则 |
| **8 位同步码** | 本机随机生成，换设备输入同一串 → 读写同一份数据 | 跨设备同步命运簿/图鉴（像 Wi-Fi 密码） |
| **账号（用户名+密码）** | 需要云函数签发登录凭证 | ⚠️ 当前套餐不支持云函数，暂缓 |

### 4. 数据流（每个功能的读写路径）

- **云命运簿**：占卜完成 → 本地保存 → 同时写入 `readings`（字段：`code`=同步码、`seed`、牌面 JSON）→ 打开命运簿/同步时按 `code` 查询合并
- **研途图鉴**：不直接存云端——由命运簿记录**本地计算**（抽到过哪些牌）
- **心事墙**：发帖 → `wishes` 写入一条；点亮 → `lights` 写一条「设备ID+帖子ID」（文档 _id 天然防重复点亮）；点亮的次数 = 统计 `lights` 里该帖的数量

### 5. 为什么账号登录暂时不可用

「个人版」套餐的限制（已在控制台实测）：
- 创建云函数 → `Creation failed`（代码包 0 字节）
- 添加安全域名 → `当前套餐无法执行此操作`

账号登录依赖云函数 `auth`（签发登录凭证），因此暂缓。游戏代码已做优雅降级：云函数缺失时自动提示「使用访客同步码」。

## 五、安全规则与管理员台

### 集合安全规则（控制台设置，必须精确）

| 集合 | 规则 | 原因 |
|---|---|---|
| `wishes` / `lights` / `readings` | `{"read":true,"create":true,"update":"doc._openid == auth.openid","delete":"doc._openid == auth.openid"}` | 人人可读可发；只能改/删自己创建的文档（防止恶意删除他人心事/记录） |
| `users` | `{"read":false,"write":false}` | 浏览器彻底无法直读用户数据与密码哈希；云函数走管理员权限不受影响 |

> 若控制台安全规则不支持 create/update/delete 分项（报语法错误），退回 `{"read": true, "write": "doc._openid == auth.openid"}` 并告知开发者。

### 管理员台（Yaya）安全设计

- **身份判定在云端**：云函数 `auth` 中 `ADMIN_NAME = "Yaya"`（精确匹配）；注册时自动标记 `role: "admin"`，老账号首次登录自动补标；
- **一次性令牌**：Yaya 登录成功时，云端生成 24 字节随机 `adminToken` 存入 users 文档并只返回给登录者；每次登录轮换，旧令牌作废。前端仅在内存保存令牌，刷新页面需重新登录；
- **管理操作逐次校验**：`adminStats` / `adminDeleteWish` 每个请求都必须携带令牌，云端比对 Yaya 记录中的当前令牌，不匹配返回「管理员验证失败」；
- **登录态真实校验**：进门前端调用 `refreshAuthState()` 与云端核对会话，失效即清除本地记忆，防止「本地自认为已登录」；
- 管理台功能：注册用户列表（用户名/注册时间/角色标记）、全局统计（用户数/命运簿/心事/点亮）、心事管理（删除帖及点亮记录）；
- **安全自检**：`node scripts/check_cloud.mjs` 会额外探测 `users` 集合是否可被浏览器直读，泄漏立即报红。

## 六、身份认证 v2 配置（两层权限，缺一不可）

CloudBase 新版身份认证要求**两层权限都配齐**，最终权限 = 角色权限 ∩ 集合安全规则：

| 层 | 管什么 | 在哪配 | 粒度 |
|---|---|---|---|
| ① 角色资源权限 | 该类用户能否访问数据库/云函数 | 身份认证 → 权限控制（添加自定义策略） | 粗：只能选「文档型数据库」「云函数」等资源类型，**界面上无法选集合** |
| ② 集合安全规则 | 哪个集合、哪些文档、谁能改删 | 数据库 → 集合 → 权限设置 | 细：每个集合一份规则 |

### 必做清单

1. **登录方式**（身份认证 → 登录方式）：启用「**匿名登录**」+「**自定义登录**」，并下载自定义登录私钥
2. **安全来源列表**（环境 → 安全来源列表）：加入站点域名 `cloud1-d9gqiv9hvb5ead833-1499970026.tcloudbaseapp.com`
3. **权限控制**（身份认证 → 权限控制）：给「匿名用户」「注册用户」各加两条策略——资源类型「文档型数据库」（读写、所有数据）+ 资源类型「云函数」选 `auth`（允许调用）
4. **集合安全规则**：见「五、安全规则与管理员台」

### 自定义登录私钥（敏感凭证）

- 私钥文件 `tcb_custom_login.json` 放在云函数目录（与 `index.js` 同级），随云函数一起上传
- 云函数优先用私钥签发 ticket（`@cloudbase/node-sdk` + credentials），无文件时回退微信内置 `cloud.auth().createTicket()`
- **已加入 .gitignore，绝不进公开仓库**；每重新生成一次私钥，旧私钥 2 小时后失效
- 本地验证：`node scripts/_diag_ticket.mjs`（读取私钥并试签一张 ticket，成功即密钥有效）

### 管理员（Yaya）

官方规定只有「组织成员」才能被赋予管理员角色，注册用户需先在「组织架构 → 导入注册用户」转为组织成员（受套餐用户数限制）。本项目改用**云函数内校验一次性令牌**：云函数以服务端管理员权限运行，不受角色策略限制，无需转换用户类型。

## 七、常见报错对照表

| 报错 | 含义 | 解法 |
|---|---|---|
| `unauthenticated / credentials not found` | 未登录且无匿名会话 | 控制台「登录方式」启用匿名登录 |
| `login_type_disabled` | 「匿名登录」未在控制台启用 | 身份认证 → 登录方式 → 启用匿名登录 |
| 权限拒绝 / `permission denied` | 角色策略或集合规则未放行 | 角色加「文档型数据库」策略 + 检查集合安全规则 |
| `当前套餐无法执行此操作` | 个人版套餐对域名/函数的限制 | 用环境自带托管域名；必要时升级套餐 |
| 首次访问出现「风险提醒」 | 测试域名官方提示页 | 点「确定访问」；正式运营绑定备案域名 |
